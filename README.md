# OVER.INDEX

Overwatch 영웅의 역할, 하위 역할, 스킬 정보를 한눈에 확인할 수 있는 영웅 탐색 웹 애플리케이션 입니다.

OverFast API를 활용하여 실제 Overwatch 영웅 데이터를 불러오고, 역할별 영웅과 각 영웅의 상세 정보와 스킬 영상을 확인할 수 있도록 구현했습니다.

---

### 주요 기능

- 영웅
  - 목록 조회
  - 상세 정보 조회
  - 포지션별 조회
  - 역할 및 서브 역할 정보 제공
  - 능력치 정보 제공
  - 스킬 정보 제공
  - 간 상성 정보 제공

- 맵
  - 목록 조회
  - 상세 정보 조회
  - 포인트별 정보 제공
  - 추천 / 비추천 영웅 조회
  - 포인트별 추천 / 비추천 영웅 조회

- 영웅 및 맵 검색

## 배운점

### 이미지 파일 관리 및 배포 경로

개발 초기에는 public 폴더에 이미지를 저장하고 절대 경로로 사용했다. 로컬 환경에서는 정상적으로 동작했지만 GitHub Pages 배포 후 프로젝트의 base 경로로 인해 이미지 경로가 정상적으로 처리되지 않는 문제가 발생했다. 이후 이미지 파일들을 src/assets로 이동하고 import하여 사용하는 방식으로 변경했다.

### Swiper의 overflow와 hover shadow 처리

swiper slide에 hover했을 때 shadow 효과를 넣었는데 swiper에 overflow-hidden이 들어가있어서 shadow가 잘리는 현상이 생겼다. swiper가 들어가는 컴포넌트 파일 말고 본 파일에 overflow-hidden을 넣고, swiper의 className에 overflow-visible!을 넣어서 가려지는것을 해결하였다.

### 기본 파일 세팅

이번 프로젝트때 header,footer만 기본적으로 만들어 놓고, loading과 pageTitle, scrollTop은 나중에 만들어서 넣었는데 이런 순서로 작업하니 나중에 이것들을 빼먹은 페이지가 나오고 그걸 하나하나 확인하는 번거로운 과정을 거쳐야 했다. 앞으로는 첫 파일 세팅때 header, footer, loading, PageTitle 이 네가지 바로바로 세팅해야겠다고 느꼈다.

### 외부 API CORS 문제와 로컬 데이터활용

OverPicker API를 사용하여 영웅의 카운터 및 시너지 정보, 맵 포인트별 추천·비추천 영웅 정보를 가져오려고 했으나, 브라우저에서 API 요청 시 CORS 정책으로 인해 정상적으로 데이터를 받아올 수 없는 문제가 발생했다.

이를 해결하기 위해 필요한 데이터를 직접 정리하여 JavaScript 객체와 배열 형태의 로컬 데이터로 변환하고, 프로젝트에서 필요한 데이터와 API 데이터를 조합하여 사용하는 방식으로 변경했다.

또한 별도의 JS 파일에서 맵 포인트명과 포지션명 등의 번역 데이터를 객체로 관리하고, API에서 받아온 데이터와 조합하여 사용했다. 이를 통해 객체와 배열을 활용하여 데이터를 구조화하고 필요한 형태로 가공하는 방법에 익숙해질 수 있었다.

이 과정을 통해 외부 API를 사용할 때는 기능 구현뿐만 아니라 CORS와 API 제공 환경, 배포 환경까지 고려해야 한다는 점​을 배웠다.
